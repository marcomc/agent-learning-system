# Coherent Learning Promotion

Read before changing instructions or declaring a learning integrated. The editor
owns one proposal and reuses the existing review coordinator and ledger. Preserve
the captured experience in the learning archive; the active instructions retain
the smallest coherent operational contract, not a growing history of incidents.

## Review the whole affected contract

Read governing user/global/project policy, the complete owning instruction or
skill, its relevant references and the affected composed output. Identify which
files an agent actually loads for the affected task. Follow the real precedence
and user authority; a council cannot vote to override higher instructions or
approve a new user decision. Expand only along affected dependencies.

For every learning choose one disposition: already-covered, clarify, refine,
merge, replace, relocate or add. Prefer editing an existing rule over restating
it. A replacement names the superseded behavior and evidence for changing it;
merges preserve supported conditions and negative cases. An already-covered
outcome changes no instructions. A code defect may need a scoped code change
rather than another directive. Keep actual choices and unresolved conflicts
pending with a concrete next action.

Prepare the complete proposed source edit with before/after snapshots. Compare
it with existing rules and consumers before applying it. Record five judgments:

| Check | Required reasoning |
| --- | --- |
| Hierarchy | Applicable superior policies, authority and precedence are preserved |
| Consistency | Overlapping rules, exceptions and contradictions are reconciled |
| Coverage | Prior required decisions survive; intentional changes and supersessions are explicit |
| Placement | Each rule reaches the acting agent at the right scope and time |
| Cost | Compare loaded paths, size changes, repetition and procedural overhead |

Measure characters and words before/after; report actual tokens when a suitable
tokenizer is available, otherwise leave them unknown. Include always-loaded
policy and conditionally reached references in the read-path assessment. Explain
any growth by its operational benefit and why refinement or narrower routing is
insufficient. No universal character limit or word reduction overrides required
coverage. A short document with costly indirection can still be worse.

## Proportionate council

| Level | Trigger | Required review |
| --- | --- | --- |
| Local | Unchanged/already-covered targets or one non-semantic clarification | Editor checks all five judgments and saves a report |
| Peer | One bounded target with a new/refined operational rule | One independent reviewer covers both coherence and ergonomics |
| Council | Multiple changed owning targets, changed global policy, merge/replacement/relocation, authority change, resolved conflict or material context growth | Two independent reviewers: policy/coverage and ergonomics/cost |

These are minimum levels; uncertainty or an explicit request may select a
stronger review while retaining that level's independence requirements.
The deterministic receipt gate escalates from changed-target count, operation and risk
flags. The editor also escalates uncertain scope or material loaded-context growth.
Do not split a coherent change into smaller receipts to evade its required level.
Reviewers receive the same frozen proposal, evidence and affected context, not
each other's conclusions. Use existing independent current reviews when they
cover these lenses. Keep one editor; reviewers return reports, not competing edits
or nested review/learning loops. Model/effort selection follows current verified
availability and task risk; a role does not prescribe a model family.

Reconcile every actionable finding before acceptance. A majority vote or bare
"approved" is insufficient. Changed semantic inputs invalidate the affected
reviews. Group unchanged already-covered targets without turning a no-op into a council.
Pure propagation to byte-identical copies may reuse reviewed source evidence,
but the final receipt must bind the actual current distribution proof.

## Receipt contract

The integration manifest requires `coherence` version 1 with:

- `editor`, `level`, empty `unresolved`, and `checks` containing substantive
  reasoning for hierarchy, consistency, coverage, placement and cost;
- `context`: current absolute file/hash references, including `role: policy`;
- `targets`: owning path, kind, operation, rationale, immutable `before`
  file/hash reference and a growth rationale when words or characters increase;
- `risks`: boolean authority_change, resolved_conflict and material_growth;
- `reviews`: role, reviewer identity, pass verdict, proposal_sha256 and a hashed
  evidence report containing that proposal hash. Local/peer use role reviewer;
  council uses policy and ergonomics with distinct identities from the editor.

Every covered file is either a target or explicit context. Full deployed skill
trees and generated consumers are bound by the integration proof. Reviewer IDs
and report hashes establish traceability, not authenticity or semantic truth:
the coordinator must corroborate actual independent review execution and read
the reasoning. Empty or stale attestations cannot replace that work.

Use the configured learning helper to freeze the proposal before dispatching
reviewers and to validate the final receipt. `coherence-proposal --manifest FILE`
checks current distribution and emits the required level, size deltas and proposal
hash without approving it. Attach actual reports, then run integration-check,
integration-record and integration-audit. A report must name the exact frozen
proposal; changed context, source, consumers or review evidence requires recheck.
Old distribution-only receipts remain historical evidence and cannot establish
current integrated status under this contract.

## Cumulative review

Before closing each changed target, assess its complete composed contract, not
only the latest diff. The weekly integrated audit revisits affected families,
recurrence and size trends across repeated promotions. Read recent coherence
receipts and the prior weekly snapshots for changed families and record per-target
coverage in the run report, including when no lexical candidate was found. Lexical duplicates and
budget warnings are discovery signals; classify them semantically. Consolidate
unnecessary repetition, retain justified independently loaded rules, and reuse
this same council/receipt path for resulting edits. Record preserved coverage
and superseded rules outside the active prompt; avoid adding a new directive
for each audit finding or starting a separate perpetual governance loop.
